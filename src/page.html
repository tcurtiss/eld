                  How to use the explorer

                  Click a node to toggle its dependencies in magenta and dependents in teal. Double-click a component to expand its subsystems, or a subsystem to show its symbols; Shift+Enter also expands a focused node. Drag nodes to hold their positions; press Escape to release. Arrow keys move a focused node. Pan the background and scroll to zoom; Expand fills the window and Escape returns. A highlighted item also shows its relationships hidden by display limits as thin arrows. Arranged by connections, items that make up a larger share of each other’s references sit closer together, using every relationship among the displayed items, not only the drawn arrows; a focused item starts at the center. Colors show connected groups found among the displayed items; switch Color by to see top-level directories. Labels that would overlap are hidden until you zoom in or highlight an item. Arranged by number of users, items with more distinct dependents stay in inner bands. Use Dependency depth to explore layering.

                  The explorer follows references between live sections. Neighborhood depth adds related items; cells and arrows always represent direct references. Caller share uses all external references in the image, including hidden relationships. Symbol ranges can overlap and are not added to physical byte totals.

                  Data format for your own linker export

                  The page reads two JSON formats, either plain or gzip-compressed (.json.gz). The columnar format is about a quarter of the size and parses faster; use it for large images. Everything runs in your browser and nothing is uploaded.

                  Columnar format. String tables plus one array per attribute, indexed by section number. Directories and files form a tree of [parent, name] entries (-1 is the top level); C++ scopes work the same way, and a section's full name is its scope chain plus its leaf name. kind: 0 code, 1 read-only data, 2 initialized data, 3 bss. flags: 1 eliminated by garbage collection, 2 root, 4 hot. References are grouped by source: section i refers to targets[offsets[i] … offsets[i+1]-1], with relocation counts in counts (leave it out if every count is 1).

                  {
  "format": "fia-columnar", "version": 1,
  "title": "soc-fw r1234",
  "regions": { "RAM": 536870912 },
  "compression": { "patterns": ".*clade*",
                   "codeRatio": 0.30, "dataRatio": 0.50, "decompressBufferBytes": 0 },
  "strings": {
    "dirs":   [[-1, "net"], [0, "tcp"], [1, "core"], [-1, "platform"], [3, "boot"], [4, "core"]],
    "files":  [[2, "tcp_out.c"], [5, "start.c"]],
    "scopes": [[-1, "net"], [0, "Socket"]],
    "outs":   [".text", ".text.z", ".rodata", ".rodata.z", ".data", ".data.z", ".bss"]
  },
  "sections": {
    "count": 4,
    "size":  [312, 188, 940, 132],
    "file":  [0, 0, 0, 1],
    "out":   [0, 1, 0, 0],
    "kind":  [0, 0, 0, 0],
    "flags": [4, 0, 1, 2],
    "scope": [-1, 1, -1, -1],
    "name":  ["tcp_output", "send", "tcp_debug_dump", "Reset_Handler"]
  },
  "refs": { "offsets": [0, 0, 1, 2, 2], "targets": [0, 0], "counts": [2, 1] }
}

                  Object format. One object per section in nodes (id, name, path, kind, size, and optionally live, root, hot, out, class) and one per reference in edges (src, dst, optional count). title, regions and compression are the same in both formats.

                  In both formats, subsystems are the first two directories of a section's path and colors follow the first directory. Include the sections garbage collection discards; they feed the eliminated-code views. Mark entry points, vector tables and KEEP sections as roots; without any, live sections nothing refers to are treated as roots. Sections whose output section matches the compression patterns count as stored compressed; hot sections stay uncompressed in projections. A few hundred thousand sections analyze in seconds; for millions, merge sections per object file before exporting.
